# الباك إند في سَند

الخادم جزء من نفس مشروع TanStack Start (لا يحتاج خدمة منفصلة): واجهة REST على `/api/*`، قاعدة بيانات PostgreSQL، وثلاثة وكلاء: **السيرة الذاتية**، **الوظائف**، **المقابلة بلغة الإشارة السعودية**.

```
المتصفح (واجهة Lovable كما هي)
   │  React context (src/lib/sanad-context.tsx) ← يقرأ ويحفظ كل شيء عبر /api
   ▼
src/routes/api/$.ts ──► src/server/http/api.ts (التوجيه، التحقق، CSRF، الصلاحيات)
                          ├─ services/   حساب المرشح، الطلبات، الخط الزمني، المواعيد، التقارير
                          ├─ agents/cv/        وكيل السيرة الذاتية
                          ├─ agents/jobs/      وكيل الوظائف + المطابقة
                          └─ agents/interview/ وكيل المقابلة + معجم لغة الإشارة السعودية
                          ▼
                   PostgreSQL (Drizzle ORM) — مدمجة محليًا (PGlite) أو خادم حقيقي عبر DATABASE_URL
```

## التشغيل

```bash
npm install
npm run dev          # http://localhost:3000 — تُنشأ قاعدة البيانات تلقائيًا في .data/pglite
npm test             # 125 اختبارًا: الواجهة + الخادم (رحلة كاملة عبر HTTP على قاعدة في الذاكرة)
npm run build && npm start
```

على Windows شغّل الاختبارات من مسار يبدأ بحرف كبير (`C:\...`)؛ مسار `c:\` الصغير يجعل vitest يحمّل نفسه مرتين ويفشل كل الملفات.

الإعدادات كلها في [.env.example](../.env.example). بدون أي مفتاح يعمل كل شيء بمحركات محلية؛ مفتاح Claude يرفع الجودة (انظر «حدود معروفة»).

## قاعدة البيانات

PostgreSQL بمخطط واحد، والترحيلات (migrations) داخل الكود في `src/server/db/migrations.ts` وتُطبّق تلقائيًا عند التشغيل. للإنتاج ضع `DATABASE_URL` لأي PostgreSQL (Supabase أو Neon أو RDS) دون تغيير أي كود.

| الجدول | المحتوى |
|---|---|
| `users`, `sessions`, `user_settings` | الحساب، الجلسات (يُخزّن hash الرمز فقط)، الموافقات والإعدادات |
| `cv_documents`, `cv_profiles` | ملف السيرة (bytea + sha256) والنص المستخرج، والمهارات والخبرات المستخرجة |
| `jobs`, `job_matches`, `agent_runs` | الوظائف (المدمجة + التي يجلبها الوكيل)، نسبة التوافق لكل مستخدم مع السبب، سجل تشغيل الوكلاء |
| `applications`, `application_events`, `interview_schedules` | حالة كل طلب، والخط الزمني لكل مرحلة، وموعد المقابلة |
| `job_preferences`, `job_skill_overrides`, `training_progress` | تفضيلات التواصل وخطة التهيئة، تعديلات الشركة على المهارات، تقدم التدريب |
| `interview_sessions`, `interview_questions`, `interview_answers`, `interview_events` | جلسة المقابلة، الأسئلة المبسطة وقائمة فيديوهات الإشارة، المسودات والإجابات المعتمدة، الأحداث بين الجهازين |
| `interpreters`, `reports` | المترجمون الاحتياطيون، تقارير المقابلات (الإجابات المعتمدة فقط) |

## الحسابات والأمان

- كلمات المرور: scrypt مع salt لكل مستخدم. نفس رسالة الخطأ ونفس الزمن سواء كان البريد موجودًا أم لا.
- الجلسة: رمز عشوائي 256-bit في كوكي `HttpOnly; SameSite=Lax` (و`Secure` في الإنتاج)، تُخزّن قاعدة البيانات الـ hash فقط، مع تمديد تلقائي.
- كل طلب يغيّر بيانات يجب أن يأتي من نفس الأصل ويحمل الترويسة `X-Sanad-Client: web` (حماية CSRF).
- حدّ للمحاولات: ١٠ محاولات دخول لكل بريد و٣٠ لكل IP كل ١٥ دقيقة.
- مراحل الطلب التي تقررها الشركة (قيد المراجعة، القبول، الرفض) مرفوضة لحساب المرشح؛ المرشح يقدّم، وينسحب، ويكمل المقابلة.
- الصفحة تُعرض من الخادم (SSR) ببيانات الحساب مباشرة، فلا تظهر بيانات «أحمد» التجريبية لحظةً قبل بياناتك. الزائر غير المسجّل يرى التجربة التوضيحية الأصلية كما هي.

## وكيل السيرة الذاتية

`POST /api/cv` (PDF أو DOC أو DOCX حتى ١٠ ميجابايت، ويُتحقق من محتوى الملف لا امتداده فقط) ثم `POST /api/cv/analyse`، والواجهة تتابع الحالة حتى `analysed`.

الوكيل يقرأ السيرة كما يقرؤها مختص توظيف، وليس بالبحث عن كلمات فقط:

1. **استخراج النص**: PDF عبر unpdf، DOCX عبر mammoth، وDOC القديم بقراءة نصوص UTF-16.
2. **تقسيم السيرة إلى أقسامها** (`agents/cv/sections.ts`): الملخص، الخبرات، التطوع، التعليم، المهارات، الشهادات، اللغات، المشاريع. يتعرف على العناوين بالعربية والإنجليزية، ومنها العناوين في نفس السطر مثل «المهارات: Excel، SQL».
3. **قراءة كل وظيفة** (`agents/cv/experience.ts`):
   - يستخرج المسمى والجهة والمدينة وتاريخ البداية والنهاية والإنجازات، سواء كانت في سطر واحد («محلل بيانات - شركة المراعي - 2022 - الآن») أو في عدة أسطر (المسمى، ثم الجهة، ثم التاريخ، ثم النقاط).
   - يفهم التواريخ بكل صيغها: «Mar 2023 – Present»، «06/2021 - 02/2023»، «من يناير ٢٠٢٠ إلى مارس ٢٠٢١»، «منذ 2019»، والتاريخ الهجري «1440هـ» محوّلًا إلى الميلادي.
   - **يحسب المدة بنفسه** ويكتبها بعربية طبيعية («سنتان»، «٣ سنوات و٩ أشهر»). ويجمع سنوات الخبرة دون احتساب الفترات المتداخلة مرتين، ثم يحدد مستوى المرشح.
   - تظهر الخبرة في لوحة التحكم هكذا: `محلل بيانات · شركة المراعي · ٢٠٢٢ – الآن (٤ سنوات) — بنى لوحات Power BI`، وتُحفظ منظمة أيضًا في `experienceDetails` لأي تصميم لاحق.
4. **المهارات لأي سيرة وأي مجال**:
   - كل ما كتبه المرشح في قسم المهارات يُؤخذ حتى لو لم يكن في المعجم. تُحذف مستويات الإتقان مثل «(ممتاز)» و«Advanced» و«80%».
   - تُضاف المهارات الظاهرة في وصف الخبرات من معجم يضم ≈١٦٠ مهارة بمرادفاتها، في التقنية والبيانات والتصميم والإدارة والمالية والقانون والصحة والهندسة والضيافة والحِرف والتعليم.
   - أسماء الأدوات تبقى كما كتبها المرشح (Zendesk وMS Office)، والمفاهيم تُكتب باسم عربي موحد («Problem solving» تصبح «حل المشكلات»).
   - لا تُستخرج مهارات من اسم الشهادة الجامعية أو من بيانات التواصل.
5. **Claude** (عند توفر المفتاح) يقرأ السيرة كاملة بمستوى تفكير `high`، ويقرأ ملفات PDF الممسوحة كصور. مع كل خبرة ومهارة ينقل **دليلًا حرفيًا من نص السيرة**.
6. **التحقق**: الكود يطابق كل دليل مع نص السيرة ويحذف أي وظيفة أو مهارة لا يدعمها النص. المدد يحسبها الكود لا النموذج. ما فات Claude يكمله القارئ المحلي دون تكرار.
7. بعد التحليل تُحسب نسبة التوافق مع كل وظيفة وسببها بالعربية. المطابقة تفهم المهارات خارج المعجم بالكلمات المشتركة: «إدارة المشاريع الإنشائية» تطابق «إدارة المشاريع»، وZendesk تطابق CRM. بعدها يبدأ **بحث وظائف مخصص لهذا المرشح**.

## وكيل الوظائف

- **منصة جدارات (بديلة طاقات) وقوى لا تتيح واجهة برمجية عامة**، وجدارات تطبيق OutSystems خلف Cloudflare، لذلك لا نكشط واجهاتها الداخلية. بدلًا من ذلك:
  - **وكيل بحث حقيقي** يعمل بـ Claude عبر Tool Runner، ومعه ثلاث أدوات: `web_search` و`web_fetch` وأداة `record_job`. يخطط عباراته بنفسه ويبحث في كل مكان:
    - المصادر: إعلانات جدارات العامة، LinkedIn، Bayt، Indeed السعودية، GulfTalent، Naukrigulf، Tanqeeb، صفحات توظيف الشركات والجهات الحكومية والجامعات، وبرامج «توافق» و«مواءمة» وجمعيات الصم.
    - يفتح صفحة الإعلان نفسه، ثم يستدعي `record_job` لكل وظيفة تحقق منها.
    - تقبل الأداة الإعلان أو ترفضه وترد عليه بالسبب (رابط غير صالح، موعد منتهٍ، إعلان محفوظ مسبقًا)، فيصحّح ويكمل.
  - **عبارات البحث**: عامة لكل المدن والمجالات، وتُضاف إليها أكثر المسميات طلبًا في سير المرشحين، فيتبع الكتالوج الطلب الفعلي.
  - **بحث مخصص لكل مرشح** بعد تحليل سيرته، بمسمياته ومهاراته ومستواه (مرة كل ١٢ ساعة على الأكثر)، أو عند الطلب: `POST /api/jobs/discover`.
  - **مصادر يحددها المشرف** في `JOB_FEEDS`: بصيغة JSON بالحقول `title, company, location, mode, salary, description, skills[], url, postedAt, deadline, deafFriendlyReason`، أو RSS/Atom، وهي صيغة توفرها كثير من مواقع الوظائف.
  - **إضافة يدوية** من المشرف: `POST /api/admin/jobs`.
- يمنع التكرار ببصمة (المسمى + الجهة + الرابط بعد التطبيع)، ويُنهي الوظائف بعد آخر موعد للتقديم أو بعد ٤٥ يومًا بلا تحديث.
- يعمل تلقائيًا كل `JOBS_AGENT_INTERVAL_HOURS` ساعة، أو يدويًا: `POST /api/admin/agents/jobs/run`.
- كل وظيفة جديدة تعمل فورًا بكل ما في الواجهة: التفاصيل، خطة التهيئة وتفضيلات التواصل، التقديم، الترشيح مع **موعد مقابلة يُحدد تلقائيًا** (بعد يومين ١٠ صباحًا بتوقيت الرياض، دون تعارض في اليوم نفسه)، التقويم وملف ics، الخط الزمني في «تتبع تقديماتي»، والتقرير.

## وكيل المقابلة (الأساسية والتجريبية)

```
المسؤول يتكلم (تحويل الكلام إلى نص في المتصفح، ar-SA) أو يكتب
  → سَند يبسّط السؤال (Claude، أو قواعد محلية + الصيغ المعتمدة للأسئلة المعروفة)
  → يظهر للمرشح: نص مبسّط + فيديو بلغة الإشارة السعودية (تسلسل مقاطع من بيانات SSL)
المرشح يشير بالكاميرا («ابدأ الإشارة» ثم «إنهاء الإشارة»)
  → سَند يفهمها في سياق السؤال (المفردات المتوقعة للسؤال والوظيفة)
  → تظهر الجملة العربية التي قالها المرشح
  → 👍 «تأكيد وإرسال» = تصل إلى المسؤول   |   👎 «ليست صحيحة» = عدم فهم
مترجم احتياطي: يُحجز تلقائيًا لكل مقابلة (standby)، وينضم تلقائيًا بعد مرتين متتاليتين من عدم الفهم
(إشارة غير مفهومة أو 👎)، أو فورًا عند الضغط على «الحاجة إلى مترجم».
```

- **المسودات لا تصل للمسؤول أبدًا**؛ يصله فقط ما ضغط عليه المرشح 👍، والتقرير يحفظ الإجابات المعتمدة فقط.
- المقابلة الأساسية لا تُفتح إلا بعد الترشيح وعند حلول الموعد (يتحقق الخادم من ذلك)؛ والتجريبية متاحة دائمًا ولا تغيّر حالة الطلب.
- جهاز ثانٍ للمسؤول دون حساب: يحصل عند بدء الجلسة على `recruiterToken` يُرسل في الترويسة `x-recruiter-token` (يقرأ الأحداث، يرسل أسئلة وتفاعلات، ولا يرى المسودات).
- أضف المترجمين الفعليين: `POST /api/admin/interpreters {name, email, phone, meetingUrl}`.

### بيانات لغة الإشارة السعودية (SSL)

يقرأ الخادم `dataset/metadata/dataset.csv` و`raw/sentences.json` من مجلد البيانات (`SSL_DATASET_DIR`): **٨٧٦٣ فيديو، ٨١٩١ إشارة، ٣٦ تصنيفًا** من مكتبة الجمعية السعودية للإعاقة السمعية.

- **النص ← الإشارة** (`agents/interview/ssl-lexicon.ts`): مطابقة العبارات الأطول أولًا («صباح الخير»، «كيف حالك»)، ثم الكلمة مع إزالة السوابق واللواحق، ثم مطابقة الجذر بين الفعل والمصدر (استخدمت ↔ استخدام)، ثم مفردات المقابلة المعتمدة (احكِ ← كلام، تريد ← أريد)، وأخيرًا التهجئة بالأبجدية الإشارية للكلمات القصيرة غير الموجودة. كل كلمات أسئلة المقابلة المعتمدة تُترجم إلى فيديوهات حقيقية من البيانات.
- **الفيديوهات**: ملفات المستودع المحمّلة في ملفك هي مؤشرات Git LFS (١٣١ بايت) وليست الفيديوهات نفسها. لذلك يُشغّل سَند كل مقطع من رابطه الأصلي على sshi.sa، وإذا نفّذت `git lfs pull` داخل مجلد البيانات يقدّمها من جهازك تلقائيًا عبر `/api/ssl/videos/:id`.
- **الإشارة ← النص**، محركان:
  1. **النقاط المرجعية (landmarks)** — `scripts/ssl/`: MediaPipe Holistic يستخرج اليدين والجسم، ثم تقسيم الإجابة إلى إشارات، ثم مطابقة DTW مع قالب لكل إشارة من البيانات، مقيّدة بمفردات السؤال الحالي. البناء مرة واحدة:
     ```bash
     # Python 3.11 أو 3.12 (لا تتوفر MediaPipe لـ 3.14 بعد)
     py -3.12 -m venv .venv-ssl && .venv-ssl\Scripts\pip install -r scripts/ssl/requirements.txt
     .venv-ssl\Scripts\python scripts/ssl/build_landmark_index.py --dataset <مجلد SSL> --download \
         --categories 39_common_words,14_social_relations,19_jobs_and_careers,07_education_and_training,04_management_economics_and_accounting
     # ثم في .env.local:
     SSL_PYTHON=.venv-ssl\Scripts\python.exe
     ```
  2. **Claude vision**: يرى لقطات الإشارة مع السؤال وقائمة المفردات المحتملة، ومطلوب منه أن يكون أمينًا: إن لم يفهم يقول ذلك ولا يكتب إجابة من عنده.
  
  يُحتسب «عدم فهم» عندما تقل الثقة عن 0.35. وفي كل الحالات **المرشح هو من يعتمد الجملة**.

## ما تغيّر في الواجهة

التصميم لم يتغيّر. التعديلات ربط بيانات فقط، والنسخة الأصلية محفوظة في `../_backup_lovable_original/src`:

- `lib/sanad-context.tsx`: نفس الـ API، لكنه يحمّل الحساب من الخادم ويحفظ كل تغيير. `lib/sanad-data.ts`: صار `Job` نوعًا عامًا بدل ثلاث وظائف ثابتة، مع دالتي `findJob` و`questionsForJob`.
- `routes/__root.tsx` (تحميل الحساب أثناء SSR)، `login.tsx` (دخول وتسجيل حقيقيان مع إظهار خطأ الخادم في مكانه)، `dashboard.tsx` (إرسال ملف السيرة الفعلي وعرض المهارات المستخرجة بدل القائمة الثابتة).
- `jobs.tsx`، `jobs_.$jobId.tsx`، `coach.tsx` (اسم الوظيفة فقط، أسئلة التدريب كما هي)، `interview.tsx`، `report.tsx`، `application-tracker.tsx`، `interview-calendar.tsx`: قائمة الوظائف من الخادم بدل الثابتة. `job-card.tsx`: سبب التوافق من الوكيل.
- `meeting-room.tsx`: عند وجود حساب حقيقي فقط: فيديو الإشارة داخل لوحة المسؤول، «ابدأ/إنهاء الإشارة»، 👍 و👎، انضمام المترجم تلقائيًا، وزر «تحدث بالسؤال» للمسؤول عندما يدعمه المتصفح. للزائر تبقى المحاكاة كما كانت.
- نصوص في الواجهة ما زالت تقول «تجريبي/محاكاة» (مثل «المهارات المستخرجة · نموذج تجريبي»، «نسخة تجريبية: لا تُحفظ البيانات»). لم أغيّرها لأنها من تصميم Lovable، ويُفضّل تحديثها هناك.

## حدود معروفة

- **فهم لغة الإشارة صعب جدًا** بهذه البيانات: معظم الإشارات لها فيديو واحد فقط (٤٩٧ إشارة فقط لها أكثر من فيديو). المحركان يعطيان مسودة، والمرشح يعتمدها أو يرفضها، والمترجم الاحتياطي ينضم تلقائيًا. لرفع الدقة: اجمعوا عدة أمثلة لكل إشارة من مقابلات حقيقية (بموافقة صريحة وفق الميثاق) وأعيدوا بناء الفهرس.
- مطابقة المحرك اللغوي اختُبرت على بيانات اصطناعية فقط هنا، لأن MediaPipe لا تعمل على Python 3.14 وفيديوهات LFS غير محمّلة. تحتاج تجربة على فيديوهات حقيقية.
- بحث الوظائف على الويب والتبسيط بجودة عالية وقراءة الإشارة بالرؤية تحتاج `ANTHROPIC_API_KEY`، وهي ميزات مدفوعة الاستخدام.
- لا يوجد بعد بريد تأكيد للحساب أو استعادة لكلمة المرور، ولا واجهة لجهة التوظيف (الخادم يدعمها بالصلاحيات).
- حدّ المحاولات وجدولة الوكيل تعمل في الذاكرة، أي لخادم واحد. عند تشغيل عدة نسخ استخدم Redis وcron.
