# الباك إند في سَند

الخادم جزء من نفس مشروع TanStack Start (لا يحتاج خدمة منفصلة): واجهة REST على `/api/*`، قاعدة بيانات PostgreSQL، وثلاثة وكلاء مترابطة: **تحليل السيرة الذاتية (ATS)**، **البحث عن الوظائف**، **مطابقة الوظائف**. غرفة المقابلة (الأساسية والتجريبية) تعمل في المتصفح كما صممتها Lovable، والخادم يحفظ موعدها وتقريرها.

```
المتصفح (واجهة Lovable كما هي)
   │  React context (src/lib/sanad-context.tsx) ← يقرأ ويحفظ كل شيء عبر /api
   ▼
src/routes/api/$.ts ──► src/server/http/api.ts (التوجيه، التحقق، CSRF، الصلاحيات)
                          ├─ services/candidate.ts   الحساب، الطلبات، الخط الزمني، المواعيد، التقارير
                          ├─ agents/cv/              وكيل تحليل السيرة (قارئ ATS + Claude + التحقق + تقييم ATS)
                          ├─ agents/jobs/jobs-agent  وكيل البحث عن الوظائف (Claude + بحث الويب + الخلاصات)
                          ├─ agents/jobs/matching    وكيل المطابقة (نسبة التوافق وأسبابها وفجواتها)
                          └─ agents/pipeline.ts      تتبع مراحل كل سيرة وتسجيلها
                          ▼
                   PostgreSQL (Drizzle ORM) — مدمجة محليًا (PGlite) أو أي PostgreSQL عبر DATABASE_URL (ومنها Supabase)
```

## التشغيل

```bash
npm install
npm run dev          # http://localhost:3000 — تُنشأ قاعدة البيانات تلقائيًا في .data/pglite
npm test             # 130 اختبارًا: الواجهة + الخادم (رحلة كاملة عبر HTTP، وخمس سير ذاتية مختلفة)
npm run build && npm start
```

على Windows شغّل الاختبارات من مسار يبدأ بحرف كبير (`C:\...`)؛ مسار `c:\` الصغير يجعل vitest يحمّل نفسه مرتين ويفشل كل الملفات.

الإعدادات كلها في [.env.example](../.env.example)، والمفاتيح في متغيرات البيئة فقط (لا شيء منها في الكود).

## تسلسل العمل

| # | المرحلة | من ينفذها | تُسجَّل باسم |
|---|---|---|---|
| ١ | رفع السيرة (`POST /api/cv`) والتحقق من نوع الملف ومحتواه | الخادم | — |
| ٢ | استخراج النص (PDF عبر unpdf، DOCX عبر mammoth) | وكيل السيرة | `extract` |
| ٣ | قراءة ATS: الأقسام، الوظائف والتدريب والتطوع والمشاريع، التعليم، الشهادات، المهارات، تقييم ATS | وكيل السيرة | `read` |
| ٤ | قراءة Claude مع دليل حرفي لكل معلومة، ثم التحقق منه في نص السيرة | وكيل السيرة | `ai` |
| ٥ | المسميات الوظيفية المناسبة | وكيل السيرة | `titles` |
| ٦ | حساب نسبة التوافق مع كل وظيفة | وكيل المطابقة | `match` |
| ٧ | بحث مخصص في المصادر الموثوقة، ثم إعادة المطابقة | وكيل البحث | `job_search` |
| ٨ | العرض في نموذج الوظائف الحالي (البطاقة، التفاصيل، رابط التقديم الأصلي) | الواجهة | — |

كل مرحلة تُحفظ بحالتها (`done` / `skipped` / `failed` / `running`) وسببها في `agent_runs`، وتُقرأ من `GET /api/pipeline`. السجلات (logs) بصيغة JSON بمعرّفات داخلية فقط، دون نص السيرة أو الاسم أو البريد. فشل أي مرحلة لا يُسقط النظام: يتوقف التحليل برسالة عربية واضحة، أو يُكمل بالقارئ المحلي إن فشل Claude.

## قاعدة البيانات

الترحيلات (migrations) داخل الكود في `src/server/db/migrations.ts` وتُطبّق تلقائيًا عند التشغيل، ولا يُعدَّل ترحيل منشور أبدًا.

| الجدول | المحتوى |
|---|---|
| `users`, `sessions`, `user_settings` | الحساب، الجلسات (يُخزّن hash الرمز فقط)، الموافقات والإعدادات |
| `cv_documents` | ملف السيرة (bytea + sha256)، النص المستخرج، حالة التحليل والخطأ |
| `cv_profiles` | المهارات، الخبرات (`experience_details` لكل خبرة: المسمى، الجهة، المدينة، التواريخ، **النوع: وظيفة / تدريب / تطوع**، الإنجازات)، التعليم، الشهادات، **المشاريع**، المسميات المقترحة، كلمات البحث، المستوى، **تقرير ATS**، ونسخة القارئ |
| `jobs` | الوظائف بمصدرها (`agent` / `feed` / `employer`) ورابطها الأصلي وتاريخ النشر وآخر موعد، وبصمتان لمنع التكرار |
| `job_matches` | نسبة التوافق لكل مستخدم ووظيفة، مع السبب والمهارات المتطابقة **والناقصة** |
| `agent_runs` | كل تشغيل للوكلاء: مراحل تحليل كل سيرة، وكل بحث (العدد، المصادر وحالتها، عبارات البحث) |
| `applications`, `application_events`, `interview_schedules` | حالة كل طلب، والخط الزمني لكل مرحلة، وموعد المقابلة |
| `job_preferences`, `job_skill_overrides`, `training_progress`, `reports` | تفضيلات التواصل، تعديلات الشركة على المهارات، تقدم التدريب، تقارير المقابلات |

**الخصوصية وRLS** (الترحيل `0006_row_level_security`): Row Level Security مفعّل على كل الجداول بلا سياسات، أي «رفض افتراضي». خادم سَند مالك الجداول فلا يتأثر، ويقيّد كل استعلام بالمستخدم المسجّل (مُختبر: لا يصل مستخدم إلى سيرة أو نتائج غيره). وإن كانت القاعدة على Supabase تُسحب الصلاحيات من دوري `anon` و`authenticated`، فلا تكشف واجهة Supabase العامة أي بيانات.

> **عن Supabase**: المشروع لم يكن مجهزًا له (لا إعدادات ولا مكتبة Supabase)، فأبقيت الإعداد الحالي: الدخول والجلسات في خادم سَند، والملفات في PostgreSQL. لنقل القاعدة إلى Supabase ضع رابطها في `DATABASE_URL` فقط. استخدام Supabase Auth وStorage بدلًا من ذلك قرار مستقل يحتاج نقل الحسابات.

## الحسابات والأمان

- كلمات المرور: scrypt مع salt لكل مستخدم. نفس رسالة الخطأ ونفس الزمن سواء كان البريد موجودًا أم لا.
- الجلسة: رمز عشوائي 256-bit في كوكي `HttpOnly; SameSite=Lax` (و`Secure` في الإنتاج)، تُخزّن قاعدة البيانات الـ hash فقط.
- كل طلب يغيّر بيانات يجب أن يأتي من نفس الأصل ويحمل الترويسة `X-Sanad-Client: web` (حماية CSRF). حدّ للمحاولات في الدخول.
- مراحل الطلب التي تقررها الشركة (المراجعة، القبول، الرفض) مرفوضة لحساب المرشح.

## وكيل تحليل السيرة الذاتية (ATS)

`POST /api/cv` (PDF أو DOCX حتى ١٠ ميجابايت، ويُتحقق من محتوى الملف لا امتداده فقط) ثم `POST /api/cv/analyse`.

1. **الأقسام** (`agents/cv/sections.ts`): الملخص، الخبرات، التطوع والأنشطة، التعليم، المهارات، الشهادات والدورات، اللغات، المشاريع، الجوائز. يعرف العناوين بالعربية والإنجليزية وبأشكالها («SUMMARY :»، «CERTIFICATIONS AND COURSES»، «المهارات: Excel، SQL»).
2. **الخبرات** (`agents/cv/experience.ts`):
   - يجمع لكل خبرة سطورها في أي تخطيط: سطر واحد («محلل بيانات - شركة المراعي - 2022 - الآن»)، أو المسمى ثم الجهة ثم التاريخ، أو التاريخ قبل المسمى، أو التاريخ والمدينة بين الإنجازات (ملفات PDF ذات العمودين).
   - يميّز المسمى من الجهة بالاسم الرئيس: «Core team member» مسمى، و«Google Student Developer Club» جهة.
   - **يصنّف كل خبرة**: وظيفة، أو تدريب (Co-op، Tamheer، Trainee، Intern، «متدرب»)، أو تطوع (من قسم التطوع). المشاريع في قسمها ولا تُعدّ وظيفة.
   - التواريخ بكل صيغها، ومنها الهجري. **المدة يحسبها الكود**، وسنوات الخبرة من الوظائف والتدريب فقط (لا التطوع ولا المشاريع) دون احتساب التداخل مرتين.
   - **تظهر في لوحة التحكم بلا تواريخ** كما في تصميم Lovable: «المسمى · الجهة · المدة»، مثل `Software Engineer · Salla · ٣ سنوات و٩ أشهر` و`Consultant · IT Committee · ٣ سنوات · تطوعي`. التواريخ الكاملة والمدينة والإنجازات محفوظة في `experienceDetails`.
3. **التعليم والشهادات والمشاريع** (`records.ts`): المؤهل والجهة وسنة التخرج والمعدل؛ الشهادة وجهتها؛ اسم المشروع وأدواته ووصفه.
4. **المهارات لأي سيرة** (`skills-extract.ts` ومعجم ≈٢٠٠ مهارة بمرادفاتها في كل المجالات):
   - كل ما في قسم المهارات، بعد حذف تسميات الفئات («Data & Analysis:») ومستويات الإتقان. لا يُستنتج مستوى إتقان أبدًا.
   - أدوات المشاريع، وما تثبته الشهادات، وما يظهر في الإنجازات. **لا تُؤخذ مهارة من اسم جهة** (هيئة الأمن السيبراني ليست مهارة).
   - الأدوات بأسمائها (AutoCAD، SAP، Zendesk)، والمفاهيم باسم عربي موحد («Problem solving» تصبح «حل المشكلات»).
5. **المسميات المناسبة**: من الوظائف التي شغلها (مع حذف «Trainee» و«متدرب»)، ثم من مجالات مهاراته (بيانات، ذكاء اصطناعي، أمن سيبراني، موارد بشرية، هندسة…)، مع مراعاة مستواه.
6. **تقييم ATS** (`ats.ts`): درجة من ١٠٠ و١٥ فحصًا، ولكل فحص نصيحة بالعربية:
   - بيانات التواصل، LinkedIn، الملخص، عناوين الأقسام المعيارية.
   - تواريخ كل خبرة، ووضوح المسمى والجهة، والإنجازات بالأرقام، وأفعال الإنجاز.
   - كلمات المهارات، والمؤهل، والطول، وقابلية القراءة الآلية، واللغات، والشهادات، ونوع الملف.
   - التقرير الكامل في `GET /api/cv/ats`.
7. **Claude** (عند توفر المفتاح) يقرأ السيرة كاملة كما يقرؤها نظام ATS ومختص توظيف معًا، وينقل **دليلًا حرفيًا** مع كل خبرة ومهارة ومشروع. الكود يحذف ما لا يدعمه نص السيرة، ويحسب المدد بنفسه، ويكمل ما فات Claude بالقارئ المحلي.
8. **الحسابات القديمة**: السيرة التي حُللت بنسخة أقدم من القارئ تُقرأ من جديد تلقائيًا من نصها المحفوظ، دون رفعها مرة أخرى.

## وكيل البحث عن الوظائف

- **المصادر بالأولوية**: LinkedIn Jobs، جدارات (ومنها وظائف الجهات الحكومية)، طاقات / هدف، Indeed السعودية، صفحات التوظيف الرسمية للشركات والجهات الحكومية، برامج «توافق» و«مواءمة»، ثم Bayt وGulfTalent وNaukrigulf.
- **طريقة الوصول**: هذه المنصات لا تتيح واجهة برمجية عامة لإعلاناتها، فالوكيل يستخدم الصفحات العامة فقط، عبر `web_search` و`web_fetch` من Anthropic، ولا يسجّل الدخول ولا يتجاوز أي حماية.
- **تسجيل الإعلانات**: يفتح صفحة الإعلان نفسه، ثم يسجّله بالأداة `record_job`. الأداة ترفض الإعلان وتذكر السبب في هذه الحالات:
  - رابط غير صالح.
  - موعد تقديم منتهٍ.
  - رابط لا يعمل (404 أو 410؛ يُفحص الرابط قبل الحفظ).
  - إعلان مكرر.
- **لا تكرار**: الإعلان نفسه من موقعين (نفس المسمى والجهة برابط مختلف) يُحفظ مرة واحدة.
- **الأمانة في المصادر**: لكل مصدر حاول البحث فيه يستدعي `report_source` بحالته الحقيقية (وُجدت نتائج، لا نتائج، تعذّر الوصول، يتطلب تسجيل دخول). تُحفظ الحالات وتظهر في `GET /api/pipeline`، فلا يُدّعى بحث في مصدر لم يصل إليه.
- **بحث مخصص لكل مرشح** بعد تحليل سيرته:
  - يبحث بمسمياته المناسبة (عربي وإنجليزي) ومهاراته ومستواه، وحديث التخرج يُبحث له في برامج الخريجين والوظائف المبتدئة.
  - مرة كل ١٢ ساعة على الأكثر، أو عند الطلب: `POST /api/jobs/discover`.
- **مصادر إضافية**:
  - خلاصات JSON أو RSS/Atom في `JOB_FEEDS`.
  - إضافة يدوية من المشرف: `POST /api/admin/jobs`.
  - تشغيل دوري كل `JOBS_AGENT_INTERVAL_HOURS` ساعة.
- **انتهاء الوظائف**: تُنهى بعد آخر موعد للتقديم، أو بعد ٤٥ يومًا بلا تحديث.
- **الوظائف التجريبية**: الوظائف الثلاث المدمجة للتجربة التوضيحية فقط. **لا تظهر لأي حساب حقيقي على أنها نتائج**، إلا إن كان قد قدّم عليها من قبل.

## وكيل مطابقة الوظائف

النسبة مقارنة فعلية بين متطلبات الوظيفة وبيانات المرشح، وليست رقمًا ثابتًا:

| العامل | الوزن | كيف يُحسب |
|---|---|---|
| المتطلبات والكلمات المفتاحية | ٥٥٪ | كل مهارة تطلبها الوظيفة تُبحث في مهارات المرشح، وفي المهارات التي تثبتها أدواته (Flutter تثبت تطوير الجوال)، وفي نص السيرة كاملًا بكل صيغها، كما يفعل ATS. الأداة المسماة (AutoCAD، TypeScript) تتطلب الأداة نفسها |
| ارتباط الخبرات | ٢٠٪ | المسميات التي شغلها ثم المسميات المناسبة له، ولا تُحتسب كاملة إلا مع تطابق في المهارات، **فتشابه المسمى وحده لا يرفع النسبة** |
| مستوى الخبرة | ١٠٪ | سنواته مقابل السنوات المطلوبة في الإعلان |
| المؤهل | ٥٪ | إن طلب الإعلان شهادة جامعية |
| الموقع ونمط العمل | ١٠٪ | العمل عن بُعد، أو نفس المدينة |

السبب يظهر في بطاقة الوظيفة بالعربية مع الفجوات، مثل: «لأن سيرتك تحتوي ٣ من ٤ كلمات مفتاحية للدور (Figma، التصميم وتصميم تجربة المستخدم)؛ ينقصك: بحث المستخدم». وتُحفظ المهارات الناقصة لكل وظيفة.

## ما تغيّر في الواجهة

التصميم لم يتغيّر. التعديلات ربط بيانات فقط، والنسخة الأصلية محفوظة في `../_backup_lovable_original/src`:

- `lib/sanad-context.tsx`: نفس الـ API، لكنه يحمّل الحساب من الخادم ويحفظ كل تغيير. `lib/sanad-data.ts`: `Job` نوع عام مع `findJob` و`questionsForJob`.
- `routes/__root.tsx` (تحميل الحساب أثناء SSR)، `login.tsx` (دخول وتسجيل حقيقيان)، `dashboard.tsx` (رفع الملف الفعلي، والمهارات والخبرات المستخرجة).
  - السطر الصغير تحت اسم الملف كان يقول «تحليل تجريبي بمهارات افتراضية». صار يعرض **تقييم ATS** وأهم نصيحة لصاحب الحساب. العنصر نفسه والتنسيق نفسه، والزائر يرى النص الأصلي.
- `jobs_.$jobId.tsx`: أُضيف **رابط «التقديم عبر …»** إلى الإعلان الأصلي، في نفس سطر الموقع والنمط والراتب، وبنمط الروابط الموجود في الموقع. يظهر فقط للوظائف التي لها رابط.
- `jobs.tsx`، `coach.tsx`، `interview.tsx`، `report.tsx`، `application-tracker.tsx`، `interview-calendar.tsx`، `job-card.tsx`: البيانات من الخادم بدل الثابتة، وسبب التوافق من الوكيل.
- `meeting-room.tsx`: نسخة Lovable الأصلية حرفيًا، باستثناء سطر واحد: `questionsForJob`.
- نصوص من تصميم Lovable ما زالت تقول «تجريبي»، مثل «المهارات المستخرجة · نموذج تجريبي» و«التوافق توصية تجريبية». لم أغيّرها، ويُفضّل تحديثها هناك.

## الاختبارات

- **رحلة كاملة عبر HTTP** على قاعدة في الذاكرة:
  - التسجيل، وأن الحساب الجديد لا يرى أي وظيفة تجريبية.
  - وظيفة حقيقية من الوكيل، ثم رفع السيرة وتحليلها.
  - المطابقة برابط الإعلان الأصلي.
  - مراحل التحليل كلها بحالاتها، وتقرير ATS.
  - التقديم والترشيح والموعد والتقرير.
  - الخروج والدخول من جديد.
- **وكيل البحث** بنموذج بديل يستدعي أدواته:
  - حفظ الإعلان.
  - رفض المكرر، ورفض الإعلان نفسه من موقع آخر.
  - رفض الرابط غير الصالح، والإعلان المنتهي، والرابط المحذوف.
  - تسجيل المصادر بحالاتها، ومهلة الـ١٢ ساعة.
- **ملفات غير صالحة**، والخادم يبقى سليمًا بعدها:
  - ملف txt.
  - ملف «PDF» مزيف.
  - PDF بلا نص.
  - مستند ليس سيرة.
- **خمس سير ذاتية مختلفة** (`backend-cv-diverse.test.ts`، بيانات مصطنعة):
  - تقنية معلومات (PDF بعمودين).
  - إدارة أعمال وموارد بشرية (عربي).
  - هندسة.
  - حديثة تخرج (تدريب ومشروع تخرج وتطوع).
  - مسيرة طويلة بالتاريخ قبل المسمى.
  - مع مطابقتها بوظائف مختلفة، ومنها وظيفة بنفس المسمى ومتطلبات مختلفة تبقى نسبتها منخفضة.
